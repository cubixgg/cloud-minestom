# Argument mapping

Every Cloud command component gets mirrored into a real native Minestom `Argument<?>` node
(spec.md §5) — not just the last one, and not a single greedy string. The native node is *shape
only*: client-side coloring and tab-complete structure. Cloud remains the only thing that actually
parses, validates or suggests a value, even for a component with a native mapping — see
[`spec.md` §5.4](./spec.md#54-cloud-is-the-only-parser-that-matters). If you ever find yourself
reading a value off a native Minestom `Argument` inside this library, that's a bug; the library never
does it.

## Built-in mappings

This table is generated by hand from `ArgumentMapperRegistry.createDefault()`
(`gg.cubix.cloudminestom.argument.StandardArgumentMappers`) — keep it in sync with that class,
not the other way around, if they ever drift.

| Cloud parser | Native Minestom `Argument` |
|---|---|
| `StringParser` (single mode) | `Word` |
| `StringParser` (quoted mode) | `String` |
| `StringParser` (greedy / greedy-flag-yielding mode) | `StringArray` |
| `BooleanParser` | `Boolean` |
| `IntegerParser` | `Integer`, with native `.min()`/`.max()` set when the parser has bounds |
| `LongParser` | `Long`, ranged |
| `FloatParser` | `Float`, ranged |
| `DoubleParser` | `Double`, ranged |
| `UUIDParser` | `UUID` |
| `EnumParser<E>` | `Word` — Minestom has no generic native "restricted choice" node; Cloud's own suggestions (every mapped node gets those regardless, see below) stand in for the restriction |
| `DurationParser` | `Time` (best effort — see [Known mismatches](#known-mismatches) below) |
| `PlayerParser` | `Entity`, constrained to `singleEntity(true).onlyPlayers(true)` |

## Fallback for everything else

A Cloud component whose parser has no registered `ArgumentMapper` — a custom parser you wrote
yourself, or one from a third-party Cloud extension — still gets a real native node, just not a
type-specific one:

- `Word` if the component consumes a single token.
- `String` / `StringArray` if it can contain spaces, or if it's the last component in its syntax.

Suggestions still come from Cloud either way (see [`threading.md`](./threading.md) for the suggestion
bridge's own threading requirement) — the fallback only affects native *shape*, never correctness or
completion quality beyond client-side coloring.

The one native shape this library never falls back to on its own is a flag subtree — see
[`limitations.md`](./limitations.md) for why flags degrade differently.

## Registering your own mapper

```java
MinestomCommandManager<CommandSender> manager = MinestomCommandManager.builder()
        .argumentMapper(MyCustomParser.class, (component, parser) -> ArgumentType.Word(component.name()))
        .build();
```

Exactly mirrors how `CloudBrigadierManager` lets you register a Cloud-parser → Brigadier-`ArgumentType`
mapping on other platforms. `argumentMapper(...)` adds to (or replaces an entry in) the manager's
current `ArgumentMapperRegistry`; call `argumentMapperRegistry(...)` first if you want to start from a
registry that isn't `createDefault()`'s built-in set.

## Known mismatches

`DurationParser` → `Time` is a **documented, deliberate** mismatch, not a bug: Cloud's own duration
grammar accepts multiple combined units (`"2d15h7m12s"`), while Minestom's native `ArgumentTime`
accepts one number plus a single optional unit suffix from `{d, s, t}` — no hours or minutes, but a
tick unit (`t`) Cloud has no equivalent for. Since the native argument is shape only, this is purely a
client-side coloring quirk: Cloud still parses and validates the full duration grammar correctly
server-side regardless of what the client's syntax highlighting suggests is valid.
